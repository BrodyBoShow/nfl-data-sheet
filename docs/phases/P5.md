**Step 4 decisions (2026-09-23):**
- **A stale model writes cards, not a skipped run.**
  - On a fingerprint mismatch, the run still writes every card with
    `projection_status = 4` (no projection, no lock). It logs `success` with
    `meta.model_stale = true`.
  - That differs from the plan's `skipped_model_stale`. A skipped run would leave
    yesterday's cards showing a projection from the old model.
  - Missed locks still surface through `check_projection_locks`. No new `agent_runs`
    status or migration was needed.
- **Postseason games are recognized by week.** `games.season_type` isn't among L3's
  allowed columns, so `week > 18` marks a game `outside_fit_scope`. nflverse numbers POST
  weeks after REG (docs/sources.md).
- **`lock_missed` shows only in `agent_runs.meta`.** The card isn't rewritten after
  kickoff to say the lock was missed; it stays frozen showing `locked: false`.
- **No per-game band on the card.** The plan's ±1 SD band per stability bucket was
  dropped.
  - The bucket RMS residuals are 13.17–13.48 for margin, so the band was effectively
    constant and read as model uncertainty it isn't.
  - The card's `uncertainty.outcome_noise` states once that NFL results land about 13
    points from any projection, model or market.
  - `projection_log.spread_sd`/`total_sd` still record the bucket values for the grader.
  - **Those values are in-sample by construction.** They're the RMS of the same 2020–2025
    walk-forward residuals whose coverage the backtest reports. The residuals are
    out-of-sample relative to the coefficients, but the band width was set on them, so
    the report's ~68–73% coverage is not an independent check.
  - The grader measures real out-of-sample coverage on live locked games.
  - See the backtest report's interpretation.
- **`spread_key_straddle` is shown as common.**
  - It fired on 37% of 2026 captures (50% at the latest poll), with a 0.5 median book
    range.
  - The card attaches a note saying it's common context, not an alert (`docs/signals.md`).
- **Concurrent runs.** If a lock insert hits an existing row (another run locked it
  first), that game's card is skipped for this run. The next run rebuilds it from the
  stored lock.
- **Follow-up for the efficiency blend (open, not acted on in P5).**
  - β_def is 28.0 on weeks 1–4 vs. 19.6 on weeks 5+ (SE 8.7 vs. 3.1).
  - Early-season defense may be over-shrunk (`k_metric` and/or `r_def`).
  - Test it when the efficiency constants are revisited. See the report's
    interpretation.

**r-leak sensitivity mechanics.**
- The scratch run calls the production `EfficiencyAnalyst.compute()` with its metric
  config swapped for `epa_per_play` alone (2018→2019 r).
- Nothing is written to the DB; results are cached in `.cache/backtest/`.
- A parity check first recomputes 2021 week 10 with the production config. It must match
  the stored signals. Verified 2026-09-23: max |Δvalue| 5e-16.

**Decisions and deviations (2026-09-23):**
- **Backtest seasons.** Out-of-sample results are **2020–2025**, not 2019–2025. 2019 is
  the first season with efficiency signals (2018 has no staged prior season), so it can
  only be training data in a walk-forward backtest.
- **Scope.** The fit and backtest use REG games only. POST games are projected live but
  flagged outside the fit scope.
- **Lock rule.** First synthesizer run with `kickoff − 6h ≤ now < kickoff`, as a named
  constant (`_LOCK_LEAD`). Observed cron ticks land 4.5–5.5h apart, so a narrower window
  would miss locks.
- **Reliability-leak sensitivity (goes in the backtest report).**
  - Efficiency's `r` was estimated from 2018–2025, so it overlaps the test seasons.
  - Re-estimate `r` from the 2018→2019 pair only, then re-run the walk-forward.
  - If the results barely move, note it as second-order. If they move materially, `r`
    must be refit walk-forward too.

## Scope
- Matchup synthesizer: joins signals per game, projects spread/total starting from
  adjusted efficiency → points regression, compares to market, writes edge cards, locks
  projections pre-kickoff into `projection_log` (immutable).
- Backtest 2019–2025 vs. historical closing lines (nflverse schedule lines, not Odds API
  historical endpoints — those cost 10× credits).

> **Design constraint (2026-09-22, before this phase starts):** the synthesizer must not
> be built against a team-only card shape. P7 (not yet built) will add player-level
> signals (Usage/role, Player efficiency) meant to pair against an opponent's matching
> unit-defense signal — e.g. a WR's `pass_epa_per_target_off` against that opponent's
> `pass_epa_per_target_allowed_def`, or an RB's rush-by-gap signal against the opponent's
> run-defense-by-gap signal (see `docs/phases/P7.md`'s scope-split note for what's behind
> these). The card-building code must be able to look up "this player's signal" and
> "the opponent's same-named counterpart signal" generically — by a shared naming
> convention (matching suffix/prefix, e.g. `_off`/`_def` on an otherwise identical signal
> name, the same pattern Phase 2's Efficiency analyst already uses for team offense vs.
> defense) — rather than hardcoding a team-vs-team join that P7 then has to retrofit.
> Slot/perimeter alignment matchups are explicitly out of scope (no free source — see
> P7's note); the only player-vs-unit pairings expected are the EPA/target-vs-allowed and
> rush-by-gap-vs-allowed kind, both built from real per-play data, not proxies. This is a
> shape constraint on this phase's design, not new work — no player-level signals exist
> to join until P7 ships.

> **Scope addition (P2, 2026):** the 2019–2025 backtest needs `team_week`/`player_week`/
> `snaps` data back to **2018** as well, purely to supply prior-season blend inputs for
> 2019's efficiency signals (the analyst always blends against `season - 1`). Fetch only
> those three tables — not all 7 the collector can stage — since the Efficiency analyst
> doesn't read the rest:
> ```
> uv run python db/migrate.py
> uv run python -m pipeline.run nflverse_bulk --force --seasons 2018-2025 \
>     --datasets team_week,player_week,snaps
> uv run python -m pipeline.run efficiency --season 2019 --week 1   # repeat per week
> ```
> **Check current Supabase storage usage against the free-tier cap before running this**
> — `docs/phases/P2.md`'s rough estimate for this exact scope (3 tables, 8 seasons of
> collector data plus 7 seasons of resulting signals) is ~130 MB raw, ~195–260 MB with
> indexes, comfortably inside the free tier on its own but worth confirming against
> whatever other tables have accumulated by the time P5 starts. `--force` is needed
> because `should_run`'s freshness gate only tracks the *live* nflverse release
> timestamp, which won't reflect wanting a historical range.
- Grader: grades every locked projection after the game, tracks closing-line value by
  signal and sector, writes calibration consumed by the efficiency analyst and
  synthesizer.
