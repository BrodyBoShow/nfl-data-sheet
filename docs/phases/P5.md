**Grader finality assumption: UNVERIFIED (2026-09-24, correctness item, open).**
- **The assumption.** `games` has no game-status column. The grader treats "the row
  carries `home_score`/`away_score`" as "the game is final". It grades the game and
  takes `spread_line`/`total_line` as the nflverse close from that row. Nothing checks
  that the score is final.
- **Evidence so far: 3 observations, 1 game. Consistent with the assumption, not proof.**
  - nflverse republished the `schedules` file twice during TNF `2026_03_ATL_GB`
    (timestamps 20:36:21 and 20:46:32 EDT, 21 and 31 minutes after kickoff).
  - Live reads at 30 and 38 minutes in had null
    `away_score`/`home_score`/`result`/`total`/`overtime` for that game.
  - Finals from weeks 1–2 carry `overtime` 0/1. `overtime` is a candidate second
    finality marker, but it's unverified.
- **What fails if nflverse ever publishes a partial score.** Correcting an earlier
  framing: `projection_grades` rows are **not** immutable.
  - The grader re-grades every in-scope game on every run and overwrites every column
    (`_upsert_grades`).
  - `result_first_seen_at` is the exception: it keeps its first non-null value.
  - The lock itself is `projection_log`, which a partial score can't touch.
  - Concretely:
    1. id_spine writes the partial into `games`, since the hash changed.
    2. The same tick's grader run marks the game `graded` against the partial:
       `margin_error`, `total_error`, `in_band_*`, `ats_*`, `ou_*`, and the
       nflverse-close columns from that row. `grade_summary` is rebuilt from it.
    3. `result_first_seen_at` is stamped with the partial's tick and **stays wrong
       permanently** (COALESCE). The result-lag measurement becomes too early.
    4. The row self-corrects on the first grader run after nflverse publishes the
       final, but only then. Until then the grade and summary are wrong, and nothing
       alerts. `auditor.check_grades` only looks for missing results.
    5. If nflverse never republishes the row, the wrong grade is permanent.
    6. Any display of finals (P6, on hold) would show the partial as final.
- **Evidence being collected.** `scripts/sample_schedule_finality.py` is read-only.
  - It polls the `schedules` timestamp.json every 2 minutes. On each change it
    re-downloads with nflreadpy's cache off (the default is a 24h in-memory cache,
    which would hide updates in a long-running process).
  - It logs each in-window game's score tuple on change.
  - Its summary flags any game whose score changed after first appearing, was scored
    while `overtime` was null, or was scored under 150 minutes after kickoff.
  - Tested with synthetic logs (`tests/test_sample_schedule_finality.py`) and
    smoke-run live against TNF.
  - The user runs it across Sunday 2026-09-27's slate.
- **Proposed defense (not built). Pick after the sampling comes back.**
  - **(a) Time floor.** A score isn't eligible as final before `kickoff + N`, where N
    is below the shortest real game.
    - This catches partials published early in a game, not late ones (a 4th-quarter
      partial at 2h45 passes any safe N).
    - **How to learn N.** From history, not by guessing: real game durations from pbp
      (first to last play wall-clock time, 2019–2025) give the shortest game. N sits
      below that, minus a margin, rounded down to 15 minutes. The sampler's
      `first_scored_min` lower tail must also sit above N.
    - Offline script; the pbp time columns get verified live and saved as a fixture
      first (CLAUDE.md).
  - **(b) Settling rule (the main defense).** Grade only once the same score has been
    seen on two grader runs at least S apart, or on one run with `overtime` non-null,
    if the sampling confirms `overtime` is only set on finals.
    - Needs two new `projection_grades` columns (`score_observed`,
      `score_observed_since`) in a new migration. A change resets `since`.
    - With ticks observed 2–7h apart, this delays grading by about one tick. Grades are
      reporting-only, so that's harmless.
  - **(c) Measurement fix.** Stamp `result_first_seen_at` only when the score passes
    (b), so a partial can't poison the lag.
  - **(d) Detection.** An auditor alert when a game's stored score differs from the
    score its grade was computed on. That catches partials and nflverse corrections
    either way.
  - **Recommendation:** (b) + (c) + (d), with (a) as a cheap extra floor once N is
    measured.

**Odds targets vs. lock windows (2026-09-24):**
- **Finding.** Every pre-kickoff odds target opened 2h after its slate's lock window.
  - Odds used a 4h `_PRE_KICKOFF_WINDOW` and the synthesizer a 6h lock lead.
    `sun_early` opened at a fixed 09:00 ET, against a 07:00 ET window for 13:00 kickoffs.
  - A tick in that 2h gap locks against the previous target's line, permanently.
  - Week 3's calendar, before the fix (lock window = the slate's earliest kickoff − 6h):

    | target | eligible at | lock window opens | gap |
    |---|---|---|---|
    | `tue_opener` | Tue 14:00Z | (no slate) | n/a |
    | `thu_pre_tnf` | Thu 20:15Z | Thu 18:15Z | +2h00 |
    | `sat_market_movement` | Sat 14:00Z | (no slate) | n/a |
    | `sun_early` | Sun 13:00Z | Sun 11:00Z | +2h00 |
    | `sun_late` | Sun 16:05Z | Sun 14:05Z | +2h00 |
    | `mon_pre_mnf` | Mon 20:15Z | Mon 18:15Z | +2h00 |

    At each window's opening, the newest target already eligible had opened 52h earlier
    for TNF (`tue_opener`), 21h for the early slate (`sat_market_movement`), 1–1.5h for
    the late slate (`sun_early`), 2h15 for SNF (`sun_late`) and 26h for MNF
    (`sun_late`).
- **Worked example: TNF `2026_03_ATL_GB`.**
  - It locked at 19:28:23Z (4.78h before kickoff) with `market_status` 2 against the
    `tue_opener` consensus from 2026-09-22 16:03Z (GB −6.5, total 44.5).
  - That line was 51.4h old at the lock. `thu_pre_tnf` didn't open until 20:15Z, and
    the next tick had not landed by 22:40Z.
  - The locked edge (+2.35 spread, −3.71 total) is measured against that 51h-old line,
    not the market at decision time.
- **Week 3's CLV sample is partly contaminated.**
  - `clv_nflv_*` (always computed) and `clv_own_*` (computed only if `thu_pre_tnf`
    captures before kickoff) both measure movement since the Tuesday opener: ~51h of
    drift that happened before the lock, plus whatever came after.
  - `ats_lock`/`ou_lock` are graded against that same stale line.
  - To find or exclude such rows, compute lock-line age at lock as
    `projection_grades.lock_line_lead_hours − lock_lead_hours` (56.2 − 4.8 = 51.4h here).
  - Any Sunday game that locks before the fix is pushed carries the same contamination.
- **Fix.**
  - `LOCK_LEAD` (6h) moved to `pipeline/core/schedule.py`. The synthesizer and
    `odds_schedule.py` both use it.
  - Every pre-kickoff target (`thu_pre_tnf`, `sun_early`, `sun_late`, `mon_pre_mnf`) now
    opens at its anchor kickoff − `LOCK_LEAD`, so it opens exactly when its slate's lock
    window does. Each tick runs odds → Market → synthesizer, so the first tick in a lock
    window captures a fresh line and locks against it.
  - Opening *earlier* than the window would fail the other way: a line captured early
    keeps aging until the lock.
  - `sun_early` is now anchored to the earliest Sunday kickoff instead of 09:00 ET. That
    also covers a 09:30 ET international game, whose window opens at 03:30 ET.
  - `ensure_week_targets` now refreshes a still-pending row's `scheduled_for`/`deadline`,
    like `weather_schedule.py` does. Captured and missed rows are never touched.
  - After the fix, every week-3 target's gap is 0h00.
  - Test: `test_pre_kickoff_targets_open_exactly_when_their_lock_window_opens` checks each
    target against the synthesizer's own `in_lock_window`.
- **Credits.**
  - Same six targets, each fired at most once, and `WEEKLY_CREDIT_CEILING` is still 21.
    The weekly maximum is unchanged at 6 calls / 18 credits.
  - The wider windows overlap: `sun_early` with `sat_market_movement`'s last hour, and
    `sun_late` with `sun_early`'s last ~3h. `decide()` fires only the newest and marks
    the other `superseded`, so an overlap never costs a second call.
  - Realized calls do rise, because a 6h window is missed less often than a 4h one. A
    simulation through production `decide()` on week 3's calendar gave mean
    calls/week 5.13 → 5.63 with jittered 2h20–6h46 tick gaps (the observed range, 2,000
    simulated weeks), and 5.02 → 5.62 at a fixed 5h spacing.
  - Nothing exceeds the old maximum of 6. Week 2 captured 2 of 6 targets.
- **Not fixed, because it would need added captures.** Each of these still locks
  against the slate's anchor capture, or the last capture of the week:
  - **SNF.** It falls under `sun_late` (kickoff ≥ 15:00 ET), whose line is now captured
    from 10:05 ET. At SNF's window open (14:20 ET) that line is up to 4h15 old, up from
    2h15 before the fix, because `sun_late` opens 2h earlier. A dedicated SNF target
    costs +3 credits a week.
  - **Later games inside a slate.** A 16:25 kickoff behind a 16:05 one locks a line
    ~20 min old. Thanksgiving's later Thursday games and the second game of an MNF
    doubleheader are in the same position, with longer lags.
  - **Days with no target.** Saturday games (weeks 15–18), and Wednesday/Friday games
    (Christmas, a week-1 international Friday). `sat_market_movement` opens at a fixed
    Sat 10:00 ET and isn't anchored to Saturday kickoffs. Re-anchoring it would move a
    capture rather than add one, but it changes what that target means and it isn't in
    week 3's calendar, so it's left for review.
- **Known gap, not fixed: a lock doesn't need a market line.**
  - `new_lock` requires only `projection_status == 1`.
  - If Market has no usable status (4 awaiting, 5 missed, or no rows), the lock still
    fires with `market_spread`/`market_total`/`edge_*` null and `market_status` 4 or 5.
  - The grader grades it **`graded`, not `no_lock`**. The margin/total errors and the
    nflverse-line picks (`ats_nflv`/`ou_nflv`) are computed. `ats_lock`, `ou_lock`, and
    every CLV column are null, since each needs the edge at lock.
  - `lock_rate` counts it as locked, and the null CLV values drop out of the CLV means
    without comment. Nothing raises or alerts.
  - The only trace is `market_status_at_lock` ∈ {4, 5} on the grade row.

**Grader decisions (2026-09-23):**
- **"Done when" amended.** It was "calibration consumed downstream". It's now "the
  grader writes grades and summaries".
  - The grader is reporting-only. Nothing reads `projection_grades`/`grade_summary`.
  - `docs/architecture.md`'s `GRADE → Efficiency/Synthesizer` arrows are marked
    deferred.
  - **Trigger for feedback:** at least one full live season graded, and a pattern (e.g.
    the weeks 1–4 β_def gap below) holding at non-exploratory status in the summary.
- **Two lines, both stored.**
  - Picks are graded against the lock line (our consensus at lock: the claim as made)
    and against the nflverse close (for continuity with the backtest).
  - `lock_line_lead_hours` shows how stale the lock line was. Week 2's Sunday lines were
    ~38h old.
- **CLV is computed two ways, never blended.** The formula is
  `sign(edge at lock) × (close − lock line)`.
  - `clv_own`: to our own last pre-kickoff capture. Same source, so it's clean. It's null
    unless a capture landed after the lock. Odds targets are sparse, so it's often
    structurally absent.
  - `clv_nflv`: to nflverse's final line. It covers every game, but it's mixed-source:
    movement plus the basis difference between nflverse's undocumented line and our
    8-book median.
  - `clv_basis_*_mean` measures the bias part: `sign(edge) × (nflverse − own close)`, on
    games whose own close was ≤ 4h pre-kickoff.
  - `lock_line_parity` rechecks that the Market analyst's selection at `locked_at`
    reproduces the stored lock line.
- **The nflverse close is final only once scored.** `spread_line` is filled in and updated
  during the week (docs/sources.md). The grader uses it only from a schedule row that
  carries a final score.
- **Sample-size honesty.**
  - Every summary row has n, a 95% CI (Wilson for rates, a game bootstrap for means and
    correlations), and a verdict:
    - `insufficient_n` below the minimum n.
    - Only 5 pre-registered primaries can read `supported`/`against`: pooled CLV (own and
      nflverse × spread and total), and the paired margin MAE vs. the lock line.
    - Every other tested slice is `exploratory`.
  - `meta` rows give the count of tests and the false positives expected at 95%.
  - **The minimum n is 50 for now, as a judgment call.** CLV and win rate converge very
    differently:
    - A 50-game CLV slice may be meaningful. A 50-game ATS slice is nowhere close
      (~1,700 decided games to tell 52.4% from 50%).
    - `CLV_MIN_N` is its own constant. It's reset from the measured per-game SD of line
      movement (`line_move_sd_*`) once that exists, not left at 50.
- **Lock rate is in the same report.**
  - `lock_rate` is locked / in scope, by week and by stability bucket. A no-lock game's
    bucket comes from its frozen card, and games never projected are `unknown`.
  - Its minimum n is 1, because it's pipeline health, not a skill claim. The Wilson CI
    still shows the uncertainty.
  - So a systematic lock failure in low-stability games surfaces in the report, not only
    in `agent_runs`.
- **Scope.**
  - Games from 2026 week 3 on (`GRADING_START`, when the synthesizer went live) that have
    kicked off.
  - POST games are graded but excluded from summaries (outside the fit). So are games
    whose kickoff moved after the lock.
  - A game never played stays `awaiting_result`, and `auditor.check_grades` flags it 36h
    after kickoff.

**Step 4 decisions (2026-09-23):**
- **A stale model writes cards, not a skipped run.**
  - On a fingerprint mismatch, the run still writes every card with
    `projection_status = 4` (no projection, no lock). It logs `success` with
    `meta.model_stale = true`.
  - That differs from the plan's `skipped_model_stale`. A skipped run would leave
    yesterday's cards showing a projection from the old model.
  - Missed locks still surface through `check_projection_locks`. No new `agent_runs`
    status or migration was needed.
- **Postseason games are recognized by week.** `games.season_type` isn't among L3's
  allowed columns, so `week > 18` marks a game `outside_fit_scope`. nflverse numbers POST
  weeks after REG (docs/sources.md).
- **`lock_missed` shows only in `agent_runs.meta`.** The card isn't rewritten after
  kickoff to say the lock was missed; it stays frozen showing `locked: false`.
- **No per-game band on the card.** The plan's ±1 SD band per stability bucket was
  dropped.
  - The bucket RMS residuals are 13.17–13.48 for margin, so the band was effectively
    constant and read as model uncertainty it isn't.
  - The card's `uncertainty.outcome_noise` states once that NFL results land about 13
    points from any projection, model or market.
  - `projection_log.spread_sd`/`total_sd` still record the bucket values for the grader.
  - **Those values are in-sample by construction.** They're the RMS of the same 2020–2025
    walk-forward residuals whose coverage the backtest reports. The residuals are
    out-of-sample relative to the coefficients, but the band width was set on them, so
    the report's ~68–73% coverage is not an independent check.
  - The grader measures real out-of-sample coverage on live locked games.
  - See the backtest report's interpretation.
- **`spread_key_straddle` is shown as common.**
  - It fired on 37% of 2026 captures (50% at the latest poll), with a 0.5 median book

  - The card attaches a note saying it's common context, not an alert (`docs/signals.md`).

  first), that game's card is skipped for this run. The next run rebuilds it from the

- Nothing is written to the DB; results are cached in `.cache/backtest/`.

**Decisions and deviations (2026-09-23):**
- **Backtest seasons.** Out-of-sample results are **2020–2025**, not 2019–2025. 2019 is
  the first season with efficiency signals (2018 has no staged prior season), so it can
  only be training data in a walk-forward backtest.
- **Scope.** The fit and backtest use REG games only. POST games are projected live but
  flagged outside the fit scope.
- **Lock rule.** First synthesizer run with `kickoff − 6h ≤ now < kickoff`, as a named
  constant (`LOCK_LEAD`, in `pipeline/core/schedule.py` since 2026-09-24 so the odds
  calendar shares it; see "Odds targets vs. lock windows"). Observed cron ticks land
  4.5–5.5h apart, so a narrower window would miss locks.
- **Reliability-leak sensitivity (goes in the backtest report).**
  - Efficiency's `r` was estimated from 2018–2025, so it overlaps the test seasons.
  - Re-estimate `r` from the 2018→2019 pair only, then re-run the walk-forward.
  - If the results barely move, note it as second-order. If they move materially, `r`
    must be refit walk-forward too.

## Scope
- Matchup synthesizer: joins signals per game, projects spread/total starting from
  adjusted efficiency → points regression, compares to market, writes edge cards, locks
  projections pre-kickoff into `projection_log` (immutable).
- Backtest 2019–2025 vs. historical closing lines (nflverse schedule lines, not Odds API
  historical endpoints — those cost 10× credits).

> **Design constraint (2026-09-22, before this phase starts):** the synthesizer must not
> be built against a team-only card shape. P7 (not yet built) will add player-level
> signals (Usage/role, Player efficiency) meant to pair against an opponent's matching
> unit-defense signal — e.g. a WR's `pass_epa_per_target_off` against that opponent's
> `pass_epa_per_target_allowed_def`, or an RB's rush-by-gap signal against the opponent's
> run-defense-by-gap signal (see `docs/phases/P7.md`'s scope-split note for what's behind
> these). The card-building code must be able to look up "this player's signal" and
> "the opponent's same-named counterpart signal" generically — by a shared naming
> convention (matching suffix/prefix, e.g. `_off`/`_def` on an otherwise identical signal
> name, the same pattern Phase 2's Efficiency analyst already uses for team offense vs.
> defense) — rather than hardcoding a team-vs-team join that P7 then has to retrofit.
> Slot/perimeter alignment matchups are explicitly out of scope (no free source — see
> P7's note); the only player-vs-unit pairings expected are the EPA/target-vs-allowed and
> rush-by-gap-vs-allowed kind, both built from real per-play data, not proxies. This is a
> shape constraint on this phase's design, not new work — no player-level signals exist
> to join until P7 ships.

> **Scope addition (P2, 2026):** the 2019–2025 backtest needs `team_week`/`player_week`/
> `snaps` data back to **2018** as well, purely to supply prior-season blend inputs for
