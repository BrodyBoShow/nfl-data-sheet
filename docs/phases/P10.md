## Scope (carried from `P7.md`, Scope)
- **Scheme analyst** (`scheme.py`), team-level, writes `signals`:
  - pass rate over expected, neutral pace
  - play-action/motion/RPO/screen rates, box counts, blitz/pressure rate
  - approximate personnel (labeled as approximate)
  - run defense by gap/direction, PFR nearest-defender coverage-proxy splits
  - participation-derived man/zone and coverage-shell tendencies, labeled as
    multi-season history (`P7.md`, "Participation labeling rule")

## What blocks it (carried from `P7.md`, step 6, "Scheme (`scheme.py`) is not written")
- **No registry entries exist** (`docs/signals.md` has none for the scheme sector).
  CLAUDE.md requires the registry, and the architecture row, before the code.
- **Several scoped inputs aren't staged:**
  - Pass rate over expected and neutral pace need pbp's `xpass` and game-state columns at
    team-game grain, and `team_week` has neither.
  - Motion/RPO rates need FTN flags by team. The `ftn` table has no `posteam`, and
    `player_game_pbp` carries only the per-player FTN columns.
  - Man/zone and shell tendencies need a team-season participation aggregate (`P7.md`,
    step 3, "Found while drafting"), and no table exists.
    `participation_player_season` can't give exact team rates.
- **What stored tables *could* support now:** team play-action/blitz/screen/stacked-box
  rates (summing `player_game_pbp` roles by team or opponent), run defense by gap (rusher
  cells by `opponent_team`), and PFR allowed-stat splits by team.
- So the first step is a registry draft, and likely a new staged aggregate plus
  migration, before any code.
