# P7 — Usage/role, player efficiency, scheme, and intel

**Status:** not started (blocked on P6)

> **Scope correction (2026-09-17):** Usage and role moves back here from P2 — P2 is
> Efficiency only now. Matchup history (previously slated to join Usage in P2) is cut
> from the plan entirely, not rehomed here either.

> **Scope split (2026-09-22, ahead of P5 locking synthesizer inputs):** player-level
> efficiency (EPA/target, success rate, YAC-oe, separation, rush-by-gap, etc.) splits out
> of Usage/role into its own analyst — Usage answers "how much does this player do,"
> player-efficiency answers "how well," and combining them would need "and" to describe
> in one docstring, which CLAUDE.md's agent-scoping rule treats as a signal to split
> before writing code. P7 is now a three-analyst phase: Usage/role, Player efficiency,
> Scheme (Intel unchanged). Full research behind this split — free/unstaged signal
> inventory, what's genuinely paid-only, and the alignment-matchup decision — captured
> below.

## Scope
- **Usage and role analyst** (`usage.py`): snap share, target share, air-yards share,
  red-zone/goal-line share, carry share, week-over-week deltas. Reads the
  `player_week`/`snaps` staged tables already populated by the Phase 2 nflverse bulk
  collector — no new external source needed.
- **Player efficiency analyst** (`player_efficiency.py`, new — see below): per-player
  rate stats, the individual-side counterpart to Phase 2's team-level Efficiency analyst.
- **Scheme analyst** (`scheme.py`): pass rate over expected, neutral pace,
  play-action/motion rate, box counts, blitz/pressure rate, approximate personnel
  (explicitly labeled as approximate), plus the run-defense-by-gap/direction and
  PFR coverage-proxy splits below. Reads the `ftn` staged table from the same Phase 2
  collector, plus (new) a player-keyed pbp aggregation and expanded `ngs`/`pfr_advstats`
  columns.
- **Intel collector**: ESPN NFL news feed, official team RSS where available, Sleeper
  trending players as a news-spike indicator. Dedupe by URL + text hash.
- Rule-based tagging only (keywords + crosswalk name matching) — team, player_id,
  category (injury, depth chart, suspension, coaching, signing/release/trade). No LLM
  calls.

### Player efficiency / defense-unit split findings (research pass, 2026-09-22)

**Free and already staged — thin reads, no new engineering:**
- `player_week.passing_epa`/`receiving_epa`/`rushing_epa` ÷ `attempts`/`targets`/`carries`
  → EPA per dropback/target/carry.
- `ngs.avg_yac_above_expectation`, `ngs.avg_separation` (receiving stat_type) → YAC over
  expected, separation.
- `pfr_advstats.rushing_yards_before_contact_avg` (stat_type=`rush`) → yards before
  contact.
- `player_week.receiving_air_yards`/`passing_air_yards` → air yards, already staged.

**Free but not yet staged — a migration change to an already-verified source, not a new
source-verification pass:**
- `ngs`: `avg_cushion`, `percent_share_of_intended_air_yards`, `avg_time_to_los`,
  `avg_intended_air_yards`, `avg_completed_air_yards` exist in nflreadpy's raw NGS output
  (see `tests/fixtures/nflreadpy_nextgen_{receiving,rushing,passing}_sample.parquet`) but
  migration `0006_staged_nflverse.sql` only kept 8 of the ~13 available columns.
- `pfr_advstats` (stat_type=`def`): `def_targets`, `def_completions_allowed`,
  `def_yards_allowed`, `def_completion_pct`, `def_adot`, `def_air_yards_completed`,
  `def_yards_after_catch`, `def_times_blitzed`, `def_times_hurried`, `def_times_hitqb`,
  `def_sacks`, `def_tackles_combined`, `def_missed_tackles`, `def_ints`,
  `def_receiving_td_allowed`, `def_yards_allowed_per_cmp`, `def_yards_allowed_per_tgt` —
  ~17 of ~20 raw columns are unstaged (only `def_pressures`, `def_missed_tackle_pct`,
  `def_passer_rating_allowed` made it into `0006`). See
  `tests/fixtures/nflreadpy_pfr_advstats_def_sample.parquet` for the full verified column
  list. **These are per-defender pass-defense production stats — genuinely useful, but
  see the coverage-assignment caveat below before treating them as a matchup stat.**

**The one net-new piece of engineering (not a new source, a new aggregation):**
nflverse's `player_week` has no success-rate flag, and pbp's `run_location`
(left/middle/right) × `run_gap` (end/tackle/guard) columns — both verified present in
`tests/fixtures/nflreadpy_pbp_sample.parquet` — are never aggregated to a player grain
anywhere in the pipeline (the P2 collector only aggregates pbp to `team_week`). A
**player-keyed pbp aggregation**, parallel to `team_week`'s existing drive/down
aggregation but grouped by rusher/passer/receiver id instead of team, is required for:
  - Player-level success rate (no raw source has this precomputed).
  - Rush EPA/success by gap and direction.
  - Stuffed rate (`yards_gained <= 0` on rush attempts).
This is the load-bearing new work in this phase — everything else above is a read of an
already-fetched, already-verified source.

**Run defense by gap/direction (unit-side):** buildable the same way — `run_location`/
`run_gap` are on every pbp row, so a team-defense aggregation split by gap is the same
kind of work as `team_week`'s existing down splits (a new group-by on the collector's
existing drive aggregation, or the new player-keyed aggregation's team-level companion).
Real, free, not yet built.

**Pressure rate / run-stop rate (unit-side):** pressure rate is buildable from
`pfr_advstats.def_pressures` (already staged) over a pass-attempts-faced denominator from
`team_week`. "Run-stop rate" in the PFF sense (a stop credited to a specific defender on a
run play) has **no free source** — PFR's `def` stat_type is pass-defense-only (targets,
completions, yards, pressures, missed tackles; no rush-defense columns at all). The
honest substitute is the team-level rush EPA/success-by-gap split above, not a
per-defender stop stat.

**Alignment (slot/perimeter) matchups — dropped from scope (decision, 2026-09-22).**
Checked FTN's full column list (`starting_hash`, `qb_location`, `n_offense_backfield`,
`n_defense_box`, motion/PA/RPO/blitz/screen flags) and NGS/PFR — no receiver-alignment or
nearest-defender-role field exists in any free staged or stageable source. Slot-vs-
perimeter pass-defense splits are not attempted. Where a directional pass-defense split
is useful, use pbp's `pass_location` (left/middle/right of field) instead — a real,
already-verified column, but a field-location split, not an alignment one; label it as
such in `docs/signals.md`, never as a slot/perimeter proxy.

**True coverage assignment — paid-only, no free substitute.** Knowing which specific
defender was matched against which specific receiver on a given play requires
tracking-derived matchup charting (PFF, Sports Info Solutions, or NFL Next Gen Stats'
matchup product — none of which are in the public `nflreadpy` release). The
`pfr_advstats.def_*` columns above are **not** this — PFR attributes targets/completions/
yards to "the nearest defender per PFR's own charting," a real and free production proxy,
but not a verified tracking-based assignment, and the `def` stat_type carries no
`position` column (a crosswalk + roster-position join is needed to know if a given
`pfr_player_id` is a CB, safety, or LB). Any signal built from these columns must be
documented in `docs/signals.md` as "nearest-defender charting," never presented as a true
matchup or a PFF-style grade — there is no free path to either.
