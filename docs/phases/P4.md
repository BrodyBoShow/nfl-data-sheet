# P4 — Market and environment

**Status:** in progress. Odds collector done: scheduling
(`pipeline/collectors/odds_schedule.py`, `db/migrations/0012_odds_snapshot_targets.sql`)
computes the weekly snapshot-target calendar (tue_opener, sat_market_movement, sun_early,
sun_late, thu_pre_tnf, mon_pre_mnf) from real `games` kickoff times and gates firing on a
per-target time window plus weekly (21 credits) and monthly (500 credits) budget
ceilings. fetch/validate/store (`pipeline/collectors/odds.py`,
`db/migrations/0013_odds_snapshots.sql`, `db/migrations/0014_odds_consensus.sql`) stores
every bookmaker per event per poll (not one reference book) plus a derived per-poll
consensus (median spread/total point + cross-book disagreement range), built and tested
against a live-verified response (`docs/sources.md`'s Odds entry, live-called
2026-09-18). Registered in the dispatcher and `pipeline.run`'s CLI job list, with its own
schedule-aware auditor check (`auditor.check_odds_targets`) instead of a generic
freshness check.

Two fixes since first standing this up, both surfaced by the first live captures:
- `pipeline/core/schedule.py`'s `resolve_season_week` and `odds.py`'s `_match_game_id`
  both took `.date()` on a raw UTC datetime instead of converting to ET first, so any
  prime-time kickoff (TNF/SNF/MNF, at/after ~8pm ET) silently resolved against the wrong
  week -- confirmed live on the actual 2026 week 2 MNF game. Fixed via a shared
  `pipeline.core.schedule.to_gameday`; `scripts/inspect_injuries_week_labeling.py`
  confirms no `injuries` rows were actually mislabeled by the same bug (no observed
  `as_of` ever fell in the danger window).
- `tue_opener`'s window was ~3.5 days wide (Tue 10am ET to Sat midnight) and fired
  Friday evening in week 2 -- not an opening line. Narrowed to close Wednesday 9am ET;
  a missed opener is accepted as better than a mislabeled one. The 2-hour/20-minute
  pre-kickoff windows (thu_pre_tnf/mon_pre_mnf/sun_late) proved too narrow the same
  week (thu_pre_tnf was missed entirely) and widened to a shared 4-hour
  `_PRE_KICKOFF_WINDOW`.

### Weather design decisions (agreed 2026-09-22, before build)
Open-Meteo verified live 2026-09-23 (`docs/sources.md`). Build order: (1) source
verification — done; (2) OSM field-geometry script + hand-reviewed `reference/stadiums.csv`;
(3) migrations; (4) `stadiums` collector, weather schedule, `weather` collector + auditor
check; (5) docs.
- **`stadiums` keyed on nflverse `stadium_id`** (not team — MetLife/SoFi are one place
  each). 41 rows: the 38 IDs on the 2026 schedule plus past international FRA00, GER00,
  SAO00. Columns: `lat`, `lon`, `roof_type` (fixed/retractable/open), `field_bearing`
  (0–179°, field is symmetric), `osm_way_id`, `known_names text[]`, source note. Roof
  *state* and surface stay per-game on `games` (retractables change per game, surfaces get
  replaced). Data lives in a checked-in CSV loaded by a hash-diffed collector, not in a
  migration (aliases get added over time; applied migrations can't be edited).
- **Coords + bearing from OpenStreetMap**: the field polygon's centroid and longest-edge
  bearing, cited by OSM way ID, picked by hand per stadium (105–125 m long, inside the
  stadium; Lambeau test: way 145797338, 113 m, ~180°, while a nearby practice field also
  matched the tag). Two IDs for one venue (GER00/MUN01 = Allianz Arena) cite the same
  way, so they can't drift. No usable polygon → `field_bearing` null.
- **Name guard, not a hardcoded fix**: each run checks `games.stadium = ANY(known_names)`
  for the game's `stadium_id`; on mismatch (or unknown `stadium_id`) don't fetch, record
  the game under `meta.unresolved`, auditor alerts. Checked 2018–2026: 182 games differ
  from their ID's most common name, but all except one are sponsor renames/spellings
  (incl. every 2026 HOU game reading the retired "Reliant Stadium"); the one real
  mislabel is `2026_05_PHI_JAX` (JAX00 but Tottenham Hotspur Stadium). A single-name
  guard would have thrown 48 false alerts in 2026 — hence the alias list.
- **Roof rule**: `roof_type=fixed` → skip; `retractable` → skip only when
  `games.roof='closed'`, else fetch (nflverse leaves it null pre-game) and label signals
  "if roof open"; `open` → always fetch, alert if `games.roof` claims dome/closed.
- **Wind is an exterior estimate**: columns named `wind_speed_10m_mph`,
  `wind_gusts_10m_mph`, `wind_direction_10m_deg`; Environment analyst frames wind signals
  as a relative indicator, never field-level wind. `field_bearing` lets it split
  along-field vs. crosswind components of that exterior estimate.
- **Snapshot schedule, 10 per game, relative to kickoff, weighted late**: T-48h, T-36h,
  T-24h, T-18h, T-12h, T-6h, T-4h, T-2h, T-1h, T-0 (kickoff). Earlier snapshots were cut
  as mostly model noise. Target-window gating like `odds_schedule` (GitHub drops cron
  runs; a missed target stays missed); each row stores actual `lead_hours`. A target with
  no hourly data yet (HTTP 400, or nulls in the window) is skipped, never filled.
  Replaces "weather 3×/day from Wed / hourly Sun" in `docs/architecture.md`.
- **T-48h is kept but flagged, not dropped** (decided 2026-09-23). Live verification
  showed T-48h lands past HRRR's reach (HRRR's extended runs go 48h ahead every 6h, so
  with run latency its live coverage ends ~42–46h out), so T-48h is GFS while T-36h onward
  is HRRR at US venues. Each row stores its schedule `target`, and T-48h rows carry
  `model_regime_break = true`. Movement comparisons ("forecast changed") start at T-36h and
  never diff T-48h → T-36h; the Environment analyst reads T-48h only as a standalone
  early look. Why keep it: it's the only forecast that exists when Sunday cards are
  drafted Friday afternoon (≈T-48h for 1pm ET kickoffs, per the architecture calendar),
  and the flag costs one column. It's flagged by target rather than inferred per venue,
  because at international venues `best_match` uses different models whose switch
  points haven't been verified — excluding the earliest snapshot everywhere is the
  conservative uniform rule.
- **Stored window**: hours H..H+4 for a kickoff in hour H (Open-Meteo precip/gusts are
  preceding-hour aggregates, so H+4 covers the game's last hour). Projection: ~215
  fetched games/season × 10 snapshots × 5 rows ≈ 10,750 rows ≈ 3 MB/season; ~2,150
  requests/season at 1.0 call each (≤10 variables).

## Scope
- Odds collector: The Odds API free tier + ESPN embedded lines as free fill-in. Append-
  only `odds_snapshots`. Credit usage logged and budgeted (~120 credits/month, see
  `docs/architecture.md` calendar).
- Weather collector: Open-Meteo (no key) + stadium coords/roof/surface. Append-only
  `weather_snapshots`, outdoor games only.
- Market analyst: open vs. current line, movement velocity, implied team totals, key-
  number crossings. No "sharp money" claims.
- Environment analyst: wind/precip flags for passing/kicking, dome/outdoor, surface,
  altitude, rest differential, travel distance, timezone crossings.
- Source verification for Odds API, ESPN embedded lines, Open-Meteo per
  `docs/sources.md`.
