## Known deviations from the plan (all documented inline where they matter)
- `Collector.store`/`Analyst.write_signals` take `(ctx, data)` not `(conn, data)` — `ctx`
  carries the open `conn` so freshness checks (`should_run`/`inputs_ready`) can also query
  the database. See `CLAUDE.md` Data contracts.
- `source_freshness` table added (not in the original migration list) — the ID spine
  collector needs somewhere to remember each source's last-seen `timestamp.json` value.
- nflreadpy's own client-side cache does **not** implement the `timestamp.json` freshness
  gate from `CLAUDE.md`/`KICKOFF.md` — that had to be built from scratch in the collector.
  See `docs/sources.md`'s "IMPORTANT" note under nflverse bulk.
- `load_ff_playerids` has ~10 known gsis_id collisions between unrelated players (a
  DynastyProcess data quality issue) — deduped deterministically, documented in the
  collector and `docs/sources.md`.

## Handoff to run live
1. Create a Supabase project (free tier) if you don't have one yet.
2. `cp .env.example .env`, fill in `SUPABASE_DB_URL` from Supabase's connection string
   (Database settings → Connection string → URI). Also add it as a GitHub Actions repo
   secret (`Settings → Secrets and variables → Actions`) once you're ready to enable the
   workflow; `DISCORD_WEBHOOK_URL` there too if you want auditor alerts.
3. `uv run python db/migrate.py` — applies all 5 migrations, tracked in
   `schema_migrations`.
4. `uv run python -m pipeline.orchestration.dispatcher` — runs the ID spine collector
   live and the auditor (P1's own scope; the dispatcher now also runs `nflverse_bulk`
   and, gated on whether a collector wrote rows this tick, `EfficiencyAnalyst` — added
   in P2's wrap-up, see `docs/phases/P2.md` and the dispatcher's own module docstring).
   Paste back any errors.
5. Spot-check in Supabase: `select count(*) from games`, `select count(*) from players`,
   `select * from agent_runs order by id desc limit 5`.
6. Once that's confirmed, push this repo to GitHub (public, per `CLAUDE.md`) and add the
   secrets from step 2 so `.github/workflows/dispatcher.yml` can run on its cron.
