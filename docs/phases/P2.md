# P2 — Efficiency, usage, and matchup history core

**Status:** in progress. nflverse bulk collector done, tested against fixtures, and
verified sourced (see `docs/sources.md`). Migration `0006_staged_nflverse.sql` written,
not yet applied live. The three analysts (Efficiency, Usage and role, Matchup history)
are not started.

## Deviations from this file's original scope (flagged, not silent)
- Migration is `0006_staged_nflverse.sql`, not `0005` — `0005` was taken by
  `source_freshness` in P1.
- The collector does not fetch/stage `load_team_stats` or `load_rosters`, despite being
  named in the original scope line. `load_team_stats`'s box-score aggregates contain
  none of Efficiency's required rate stats (success/explosive/red-zone/three-and-out/down
  splits — all pbp-only) and duplicate what pbp already supplies (yards, attempts, EPA)
  without the garbage-time filter; fetching it would stage a redundant, unused table.
  `load_rosters` only adds crosswalk fields already partially covered by
  `load_players`/`load_ff_playerids` — noted in `docs/sources.md` as a future
  crosswalk-completeness pass, out of scope here. Both were still live-verified for
  `docs/sources.md` completeness.
- Added `load_pfr_advstats` (tag `pfr_advstats`) and a `pfr_advstats` staged table — this
  wasn't in the original 6-table list but the phase's own collector-scope line named
  "PFR advanced" as a source to fetch. Not consumed by any Phase 2 analyst yet; staged
  for later Efficiency/Scheme refinement.
- `team_week` is pbp-derived only (one row per team per game, offense-side). Opponent
  adjustment is computed by the Efficiency analyst self-joining on `opponent_team` across
  the league, not by storing a second defensive row per team.
- `depth` stores only the LATEST depth-chart snapshot per team/position slot, not one row
  per player per week — `load_depth_charts` is scraped near-daily (221 distinct
  timestamps/season), so storing every snapshot would multiply row count ~30x for no
  signal value Phase 2 needs. It answers "who is QB1 right now" for Efficiency's
  starting-QB-change discount, not "who was QB1 in week 3".
- Garbage time is defined as win probability (for the team with the ball) below 5% or
  above 95% — a judgment call since `docs/signals.md` doesn't pin an exact definition.
  "Explosive play" is the common convention (20+ yard pass, 10+ yard rush), also a
  judgment call. Both are documented as constants in
  `pipeline/collectors/nflverse_bulk.py` and should get a `docs/signals.md` registry
  entry when the Efficiency analyst's signals are added.
- `pipeline/core/db.py`'s `filter_changed` was extended to accept a composite key
  (`list[str]`) as well as the original single `str` column — most P2 staged tables have
  multi-column primary keys (e.g. `player_week` on `(player_id, game_id)`), which the
  original single-column implementation couldn't hash-diff correctly.

> Usage/role and Matchup history were moved here from the original P7 slot. Both only
> need the nflverse bulk collector built in this phase — no new external source — and
> Availability impact (P3) depends on Usage's target/carry shares, so sequencing it here
> removes P3's original raw-snap-share fallback. See `docs/architecture.md` §Deviations.

## Scope
- nflverse bulk collector: pbp, player/team stats, snap counts, NGS, PFR advanced, FTN
  charting, depth charts, rosters via nflreadpy. Stores aggregates only — never raw pbp
  in Postgres.
- Efficiency analyst: opponent-adjusted EPA/play, success rate, explosive rate,
  points/drive, three-and-out rate, red-zone TD rate; pass/rush and down splits; garbage
  time filtered; prior-blended with last season per `docs/signals.md`.
- Usage and role analyst: snap share, target share, air-yards share, red-zone/goal-line
  share, carry share, week-over-week deltas.
- Matchup history analyst: player-vs-specific-opponent and team-vs-division/rival
  historical signals, recency-weighted, drawn from the same staged `player_week`/
  `team_week` tables. Low `stability` by default given small sample sizes — see
  `docs/signals.md` §Matchup history sector.
- Freshness gate: check nflverse release `timestamp.json`, skip unchanged.
- Signal registry entries in `docs/signals.md` for every signal these three analysts
  write.
