## Deviations from this file's original scope (flagged, not silent)
- Migration is `0006_staged_nflverse.sql`, not `0005` — `0005` was taken by
  `source_freshness` in P1.
- The collector does not fetch/stage `load_team_stats` or `load_rosters`, despite being
  named in the original scope line. `load_team_stats`'s box-score aggregates contain
  none of Efficiency's required rate stats (success/explosive/red-zone/three-and-out/down
  splits — all pbp-only) and duplicate what pbp already supplies (yards, attempts, EPA)
  without the garbage-time filter; fetching it would stage a redundant, unused table.
  `load_rosters` only adds crosswalk fields already partially covered by
  `load_players`/`load_ff_playerids` — noted in `docs/sources.md` as a future
  crosswalk-completeness pass, out of scope here. Both were still live-verified for
  `docs/sources.md` completeness.
- Added `load_pfr_advstats` (tag `pfr_advstats`) and a `pfr_advstats` staged table — this
  wasn't in the original 6-table list but the phase's own collector-scope line named
  "PFR advanced" as a source to fetch. Not consumed by the Efficiency analyst; staged for
  later refinement (or for Usage/Scheme in P7, since it's the same collector).
- `team_week` is pbp-derived only (one row per team per game, offense-side). Opponent
  adjustment is computed by the Efficiency analyst self-joining on `opponent_team` across
  the league, not by storing a second defensive row per team.
- `depth` stores only the LATEST depth-chart snapshot per team/position slot, not one row
  per player per week — `load_depth_charts` is scraped near-daily (221 distinct
  timestamps/season), so storing every snapshot would multiply row count ~30x for no
  signal value Phase 2 needs. It answers "who is QB1 right now" for Efficiency's
  starting-QB-change discount, not "who was QB1 in week 3".
- Garbage time is defined as win probability (for the team with the ball) below 5% or
  above 95% — a judgment call since `docs/signals.md` doesn't pin an exact definition.
  "Explosive play" is the common convention (20+ yard pass, 10+ yard rush), also a
  judgment call. Both are documented as constants in
  `pipeline/collectors/nflverse_bulk.py` and should get a `docs/signals.md` registry
  entry when the Efficiency analyst's signals are added.
- `pipeline/core/db.py`'s `filter_changed` was extended to accept a composite key
  (`list[str]`) as well as the original single `str` column — most P2 staged tables have
  multi-column primary keys (e.g. `player_week` on `(player_id, game_id)`), which the
  original single-column implementation couldn't hash-diff correctly.
- `snaps` and `ftn` are staged by this phase's collector but have no P2 consumer now that
  Usage moved back to P7 and Matchup history is cut — they're read by the Usage analyst
  (`snaps`) and Scheme analyst (`ftn`) when P7 gets built, per the same collector serving
  multiple later analysts. `player_week`/`team_week`/`ngs`/`depth` are Efficiency's actual
  P2 inputs.
- **Efficiency analyst design changes from a code-review pass, before any code was
  written** (see `docs/signals.md`'s "Prior blending" section for the resulting design):
  - **Point-in-time, not just "this week":** `compute()` filters current-season rows to
    strictly before the requested week (postseason weeks include the full regular season
    plus earlier postseason games — verified live that nflverse's POST week numbers
    continue incrementing from REG, e.g. 2023 REG 1–18 then POST 19–22, so a plain
    `week < before_week` comparison already does the right thing with no season_type
    branching needed). This makes the analyst backfill-ready for Phase 5, though **no
    historical backfill runs in P2 itself** — only live 2025–2026.
  - **Three-way current/prior/league blend**, not two-way: a QB/OL-change discount
    shrinks trust in the *prior* and hands that share to the *league average*, never to
    the current season. `stability = w_cur + w_prior`, not a games-based weight.
  - **Per-metric discount sensitivity**: QB/OL-continuity discounts apply to each of the
    20 base metrics scaled by a `qb_sensitivity`/`ol_sensitivity` (e.g. a QB change fully
    discounts pass splits, not at all rush splits) rather than one uniform discount.
  - **Opponent-adjustment solver**, not a one-pass leave-one-out adjustment: offense and
    defense ratings are solved jointly by fixed-point iteration, with shrinkage toward
    the league average happening in exactly one place — inside the prior-season solve
    and the final blend, never twice for the same current-season value.
  - **`points_per_drive`'s numerator moved off the game scoreboard onto `team_week`
    itself** — a new `points` column (migration `0008_team_week_points.sql`) derived
    from pbp's own `fixed_drive_result` inside the collector's existing drive aggregation,
    so it can be garbage-time-filtered and offense-only like the rest of `team_week`'s
    drive columns, instead of a whole-game total.
  - **Team abbreviation normalization**: verified live that `snap_counts`/`pfr_advstats`
    (both PFR-sourced) still carry retired franchise codes for historical seasons (`OAK`/
    `SD`/`STL`) that `pbp`/`player_stats`/`nextgen_stats` already normalize to current
    codes (`LV`/`LAC`/`LA`) — without fixing this, a team's prior-season join would
    silently miss a relocated franchise's history. `nflverse_bulk.py` now normalizes
    `snaps`/`pfr_advstats`'s team columns via a small `_TEAM_ABBR_ALIASES` map.
    **Heads-up for P1, fixed in this phase's wrap-up:** the live `teams` table (from
    `load_teams()`) turns out to hold 36 rows, not 32 — every current code plus the
    retired `OAK`/`SD`/`STL`/`LAR` aliases, since `load_teams()` is a static "every code
    ever used" reference and P1's id_spine collector stores it wholesale. Resolved via
    `teams.is_active` (migration `0010_teams_is_active.sql`, set by `id_spine`) — see
    "Fixes made after the first live run" above and CLAUDE.md's Canonical keys section.
    The Efficiency analyst still derives its own team list from which codes actually
    appear in `team_week` rather than querying `teams`, unaffected by this.
  - **`skipped_no_prior` status**: `inputs_ready` gates on the *prior* season existing
    (a week-1 run is valid and expected to produce prior+league-only signals), and a
    missing prior gets its own `agent_runs.status` value — distinct from a routine
    `skipped_fresh` — via `pipeline/core/base.py`'s `should_run`/`inputs_ready` contract
    widening to `bool | str`, and migration `0009_agent_runs_skip_reason.sql`.
  - **Backfill CLI**: `pipeline/run.py` gained `--force` (bypasses the freshness gate —
    needed after `0008` to backfill `points` into already-staged rows, and again for the
    2018–2025 `team_week`/`games` backfill below), `--season`/`--week` (target a specific
    past week for the `efficiency` job), and `--seasons`/`--datasets` (`nflverse_bulk`:
    a season range and a subset of the 7 staged tables; `id_spine`: `--seasons` only,
    for `games`/`schedules`). Used within P2 itself for the reliability-factor
    estimation's 2018–2025 backfill (see "Fixes made after the first live run" above);
    also expected to serve Phase 5's eventual backtest. See `docs/phases/P5.md`.

## Fixes made after the first live run

The live verification run (2026 Weeks 1–2) and the resulting spot-checks surfaced six
real issues, all fixed within P2's scope rather than deferred:

1. **OL-continuity discount skipped for 4 teams** ("unknown group" warnings): some
   teams' `snap_counts` rows tag the whole O-line as generic `"OL"` instead of
   `C`/`G`/`T`, with zero `C`/`G`/`T` rows at all (verified live: ARI/CHI/JAX/LA).
   `_OL_SNAP_POSITIONS` now includes `"OL"`. The original hypothesis (PFR team-code
   normalization) was a dead end — `_TEAM_ABBR_ALIASES` needed no change.
2. **QB-change discount was a binary same/different-starter flag**, not a continuity
   measure — a starter who missed half the prior season to injury (or was traded in)
   got the same full discount as a genuinely new starter. Replaced with a continuity-
   *share* formula (`docs/signals.md`'s "Prior blending" section) that credits a
   traded veteran's attempts from any team.
3. **`play_type == "no_play"` rows leaked into `team_week.plays`**: a penalty no-play
   still carries the original called play's `pass`/`rush` flag and a non-null `epa`.
   Verified live: 1,622 rows leaked across 2025–2026. Excluded, plus a `qb_kneel`/
   `qb_spike` safety net.
4. **Garbage time was a single win-probability threshold for the whole game**, which
   could trigger as early as the 2nd quarter of a blowout (one team's 51 eligible plays
   cut to 13). Replaced with a time-aware rule (Q1–Q2 never garbage, Q3 a tighter band,
   Q4/OT the original band) — see `docs/signals.md`.
5. **No path from a collector/analyst to `agent_runs.meta`**, even though the column
   existed — `Collector.store`/`Analyst.write_signals` returned a bare `int`. Widened
   to `WorkResult(rows_written, meta)` (CLAUDE.md's Data contracts section). Efficiency
   now records every team's `qb_factor`/`ol_factor`/current starter/OL overlap there.
6. **Defense signals had no year-over-year reliability concept** (`prior_discount`
   hardcoded to `1.0`) — a metric with no real season-to-season signal (e.g. 4th-down
   rate splits) got just as much prior trust as a highly persistent one. Estimated a
   reliability factor `r` per metric/side from 2018–2025 (`scripts/estimate_reliability.py`,
   full method in `docs/signals.md`'s "Prior-blend reliability r" section) and wired it
   into the blend for both offense and defense.

Also added, not fixes but scope completions:
- `teams.is_active` (migration `0010_teams_is_active.sql`, set by `id_spine`) — closes
  the "worth deciding" note below about the 36-row `teams` table.
- `id_spine` gained `--seasons` (needed to backfill `games`/`schedules` far enough back
  for fix 6's `team_week` backfill to satisfy its foreign key).
- Three verification/backfill scripts: `scripts/inspect_play_filter.py`,
  `scripts/inspect_qb_continuity.py` (calls production functions directly, not
  hand-written SQL — see CLAUDE.md's Conventions), `scripts/estimate_reliability.py`.

   2026-09-29, not fixed).** Found in P7 step 6 while choosing the player blend's r.
   - **What the blend needs.** It predicts this season's rating as `league + r·(prior −
     league)`, where the prior is last season's k-shrunk plain solve. The unbiased r for
     that is the slope of next season's rating on this season's shrunk rating
     (`r_slope`).
   - **What it uses.** `scripts/estimate_reliability.py` records the pooled correlation
     of shrunk ratings in both seasons (`r_corr`). Sampling noise in *both* seasons pulls
     a correlation down; the slope is only affected by noise in the predictor, which
     shrinkage already accounts for.
   - **Measured** (`scripts/verify_efficiency_r_slope.py`, 2018–2025, Efficiency's own
     solver, team bootstrap):
     - r_slope / r_corr is 1.08–1.38 (median 1.26) across all 36 metric-sides except
       down4, and above 1 in every one. It's systematic, not noise.
     - Examples: `epa_per_play_off` r_corr 0.416, r_slope 0.518 (90%: 0.35–0.64);

     - The recorded raw values differ slightly from this script's r_corr (e.g. 0.396 vs
       0.416). This script de-means each season before pooling; the original pooled raw
       ratings.

   2018–2026 the same day, runs 874–881).** Found in P7 step 7 part 2, while measuring
   item 1.
   - **Mechanism.** `_aggregate_team_week`'s drive aggregation used every play under a
     `fixed_drive`, try plays included.
     - A try sits inside the 20: 1,296 of 2025's 1,324 PATs at the 15, and 110 of 130
       two-point tries at the 2. So it set the drive's `closest_yardline`, and a TD drive
       from midfield counted as a red-zone trip and a red-zone TD.
     - A try alone under a `fixed_drive`, after a return score, counted as a drive.
   - **Measured, 2025 REG, `_aggregate_team_week` with vs without try plays:**
     - `red_zone_trips` 1,962 → 1,636; `red_zone_tds` 1,193 → 921.
     - League red-zone TD rate 0.608 → 0.563.
     - Team `red_zone_td_rate`: +0.045 mean. The max is 0.103 (DET def), and BAL off is
       0.095, against a cross-team SD of ~0.07, so up to ~1.5 SD. Raw team-season, not
       run through `compute()`.
